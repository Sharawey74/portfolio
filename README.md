# portfolio

Personal portfolio for Sharawey74: backend systems first, with AI services and
open-source work as supporting material. Black and white, one accent color,
every public number traced to a source file and a date.

> Status: Stage 5 of 6 done (design polish, motion audit, performance pass).
> Build order and progress: `PLAN.md`. Rules and context: `CLAUDE.md`. Design
> audit: `docs/UX-REVIEW.md`. Owner acceptance script: `docs/UAT.md`. Open
> issues and proposed fixes: `docs/ISSUES.md`. Measurements: `docs/reports/`.

## What is on the site

| Route | Content |
|---|---|
| `/` | Hero, 01 About (facts bento, stack by lane), 02 Work (three case studies as a sticky stack, two more projects), 03 Open source (PR timeline, status refreshed daily from GitHub), 04 Experience (roles, education, certifications), 05 Contact (form + direct links), footer |
| `/projects/eventora`, `/projects/recruiter-pro`, `/projects/sysplex` | Case studies: problem, animated architecture diagram, key decisions, sourced evidence, charts, screenshots, stack, limits |
| `/sitemap.xml`, `/robots.txt`, `/opengraph-image` | Generated by Next.js from the data files |
| `/dev/type` | Type and component specimen. `noindex`; 404 on the production deployment |

Press Ctrl+K (⌘K on a Mac), or the header's Search / Menu button, for the
command palette: sections, projects, pull requests, links, theme and pause.

## Stack

Next.js 16.4 (App Router, Turbopack), React 19.3, TypeScript strict,
Tailwind CSS v4 (CSS-first tokens in `src/styles/globals.css`), Lenis, Zod 4,
`next/font/google` (Newsreader, Hanken Grotesk, JetBrains Mono), `next/og`.
The contact form calls Resend's HTTP API with `fetch` (no SDK). npm.
Node 22.18 or newer (the check scripts are plain `.ts` run by Node directly).

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Local dev server |
| `npm run build` | Lists open `TODO(owner)` items, then `next build` |
| `npm start` | Serve the production build (port 3000) |
| `npm run lint` / `npm run typecheck` | ESLint 9 / `tsc --noEmit` |
| `npm run check` | Facts, contrast and one-color checks |
| `npm run check:facts` | Every claim has `source` + `asOf`; no banned claims; no private terms |
| `npm run check:contrast` | WCAG ratios for every token pairing, both themes |
| `npm run check:colors` | Only grays plus the three accent tokens (`--c1`, `--c2`, `--break`), in source and built CSS |
| `npm run check:launch` | Lists `TODO(owner)` items; `-- --strict` or `LAUNCH_STRICT=1` fails if any remain |
| `npm run report:bundle` | First-load JS per page after a build (budget for `/`: 170 KB gz) |
| `npm run test:smoke` | Playwright smoke tests against the production build (build first; `npx playwright install chromium` once) |

CI (`.github/workflows/ci.yml`) runs install, lint, typecheck, the facts and
contrast checks, build, the color check on built CSS, the bundle budget and the
smoke tests on every push and pull request. Lighthouse runs on each Vercel
preview, and a `vX.Y.Z` tag creates the GitHub Release; see `DEPLOY.md`, which
also covers environment variables, release steps and rollback. Changes are
listed in `CHANGELOG.md`.

## Where the content lives

All copy and numbers live in typed data files. Components contain no copy.

| Content | File |
|---|---|
| Personal fields (name, email, photo, bio, location, availability, GPA, resume) | `src/data/personal.ts` |
| Hero, section titles and order, every interface string, site meta | `src/data/profile.ts` |
| Projects, case studies, diagrams (`flow`), charts | `src/data/projects.ts` |
| Open-source PRs and issues | `src/data/oss.json` (snapshot) + `src/data/oss.ts` |
| Experience, education, certifications | `src/data/experience.ts` |
| Tech chips, by lane, with where each was used | `src/data/skills.ts` |
| Shared Zod schemas | `src/data/schema.ts` |

Every public claim carries a `source` (file:line or URL) and an `asOf` date.
The schemas reject a claim without them, so the build fails.
`FACTS-CHECK.md` maps each claim back to the evidence report.

## Updating

1. Edit the data file (table above). Keep `source` and `asOf` on every claim;
   a missing fact is a `TODO(owner): …` string, which renders nothing.
2. Run `npm run check` and `npm run build` locally. The facts check also reads
   the git-ignored private-terms list, which CI cannot see.
3. Commit, push a branch, open a pull request: Vercel builds a preview. Merge
   to `main` to publish.

Common edits:

- **Your name, email, bio, photo, resume:** `src/data/personal.ts` (see
  `PERSONAL-INFO-CHECKLIST.md`). Set `value` and delete `todo`. The resume
  also needs the file at `public/resume.pdf`; the photo goes under `public/`.
- **A new pull request:** add it to `src/data/oss.json` with the fields from
  `gh pr view <n> -R <owner/repo> --json title,state,createdAt,mergedAt,additions,deletions`.
  Headline numbers recompute. Merged/open status refreshes from GitHub daily.
- **A new project:** add an entry to `src/data/projects.ts`. A case study needs
  `problem`, `flow` (nodes and steps, each sourced) and a layout position for
  every node in `src/components/diagrams/layouts.ts`, or the build fails.
- **A new tech chip:** `src/data/skills.ts`, with `usedIn` naming project slugs.
- **Show or hide a section:** its `live` flag in `profile.sections`.

## Environment variables

Set in the Vercel dashboard (Project → Settings → Environment Variables), never
committed. `.env.example` lists them with notes.

| Variable | Needed for | Notes |
|---|---|---|
| `RESEND_API_KEY` | Contact form | Without all three contact variables the form is replaced by a "not connected" note |
| `CONTACT_TO_EMAIL` | Contact form | Your inbox |
| `CONTACT_FROM_EMAIL` | Contact form | A sender on a domain verified in Resend |
| `NEXT_PUBLIC_SITE_URL` | Canonical URLs, sitemap, OG, JSON-LD | Optional on Vercel (falls back to the production domain); set for a custom domain |
| `GITHUB_TOKEN` | Daily PR status refresh | Optional; raises the API rate limit. No scopes needed |
| `LAUNCH_STRICT` | Launch gate | `1` on Production makes the build fail while `TODO(owner)` items remain |
| `NEXT_PUBLIC_ENABLE_SHADER` | Stage 5 shader | Default `0` |

`/` is prerendered (and regenerated at most daily for the PR status), so a
change to the contact variables takes effect on the next deployment.

## Deploying on Vercel

1. vercel.com → Add New → Project → import `Sharawey74/portfolio`. Framework
   preset: Next.js; no build settings to change (no `vercel.json`).
2. Add the environment variables above (Production, and Preview if you want
   the form on previews).
3. Deploy. Production follows `main`; every pull request gets a preview URL.
4. Set the repository homepage to the production URL:
   `gh repo edit Sharawey74/portfolio --homepage https://<your-project>.vercel.app`.
5. Optional: a custom domain under Project → Settings → Domains, then set
   `NEXT_PUBLIC_SITE_URL` to it and redeploy.

Resend: create an API key, verify the sending domain (or use Resend's test
sender while trying it out), and use that address for `CONTACT_FROM_EMAIL`.
